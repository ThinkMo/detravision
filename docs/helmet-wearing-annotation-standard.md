# 施工监控安全帽佩戴状态标注规范（2026-10-16）

适用目标：客户两批共 41 个图片文件所代表的施工、变电站、光伏和道路作业监控场景。高质量首先指目标可判断、标签完整准确、与业务视角匹配，其次才是图像尺寸和数量。本文是新增数据的建议规范；不会自动改动现有已发布版本或用户已确认的标注。

## 推荐保留的母版信息

每个人保留独立的 person 框、关联的 head 框和 wearing_state：helmet / no_helmet / uncertain。使用 person_id 连接人员与头部；视频额外保存 sequence_id、track_id、frame_index 和 scene_group。帽子放在地上或手中时，可额外标 helmet_object 与 worn=false，不得赋予人员 helmet 状态。

母版关系信息保存在独立 JSON 中；普通 YOLO 五列标签不支持人员关联、遮挡或不确定属性，不能只靠改类别名保留这些信息。未经实现和验证，不向现有应用声称已支持这些属性。

| 字段/对象 | 框的边界或取值 | 核验要求 |
| --- | --- | --- |
| person | 人体可见部分的紧致框，截断到画面边界 | 不能用“人体上方固定百分比”代替头框；截断和遮挡单独记录 |
| head + helmet | 整个可见头部，包含佩戴的安全帽，从帽顶到下巴/可见头部下缘 | 不包含肩膀、胸口；后脑、俯视也按可见头部外缘框选 |
| head + no_helmet | 同样是整个可见头部，包含头发或普通帽子 | 棒球帽、布帽不能作为安全帽；看不清帽型时 uncertain |
| head + uncertain | 头部过小、模糊、被遮挡、背光或帽型不可判断 | 不猜标签；不参与二分类真值 |
| helmet_object（可选） | 只包安全帽实体 | 明确与头部状态框区分，不能混进同一个 helmet 类别 |

原则：完整可见的头部应紧贴轮廓；遮挡时框住能可靠定位的可见头部部分并记录遮挡，不能凭想象补出隐藏边界。严重遮挡到状态无法判断时用 uncertain。框选口径必须在整个版本保持一致。

在现有三类界面制作新版本时，可以继续使用 0=person、1=helmet、2=no_helmet；但该新版本中 helmet 明确定义为“戴安全帽的完整头部”。若旧版本 helmet 是帽壳框，保留旧版本，再逐图修订到新版本，不能统一扩大框或直接合并。

## 两种训练方案如何比较

| 方案 | 导出类别和范围 | 适用与限制 |
| --- | --- | --- |
| A：整个人员状态检测 | person_helmet / person_no_helmet，整个人员框 | 可利用 CMOT 原标注，直接定位违规人员。目标框大，但小头部仍可能看不清，需防止模型依赖服装、工地和人物身份 |
| B：人员 + 头部状态检测 | person，以及 helmet / no_helmet 两种头框 | 与佩戴依据更直接，方便核对旁边/手持安全帽、多人和弯腰案例；小头部需要保留原图细节，可能需要局部裁剪或分块推理 |

建议以 B 作为本次新增数据的主标注口径，同时保留母版以导出 A 做对照。这是针对客户场景的工程选择，不是“B 的识别率一定更高”的实测结论。

整个人框与头框的检测难度、IoU 容忍度和真值对象不同，不能比较各自 mAP 数字就断定业务识别率。相同人员框的位移在大框上往往更容易通过 IoU 门槛，因此 A 的 AP 较高也不代表未戴帽告警更可靠。

公平比较需使用相同原图、同一场景分组、相近训练预算，先把两套结果转成每个人员的佩戴判断，再比较未戴帽召回率、精确率和每图误报。视频另统计每摄像机小时误报；静态 41 张图片不能估计小时误报。分别报告头部尺度、遮挡和逆光子集。报告 no_helmet 的 AP50、AP50-95，不用 person 的高 AP 稀释违规类别结果。mAP90 的目标还应明确是 AP50≥0.90 还是 AP50-95≥0.90。

## 公开数据的映射规则

- **CMOT**：类别 1=people-helmet、2=people-no-helmet 对应整个人员状态框，其他类别是机械和材料。可导出方案 A，或作为 person 框复用；没有真实头框时不能导出方案 B 的头框。保留官方分区与 track_id；若自建业务分区，另存 custom_split，不能宣称官方基准结果。
- **SH17**：官方 `sh17.yaml` 中 YOLO 编号是 0=person、12=head、10=helmet；论文表格序号不是 YOLO 类别 ID，不能按表格位置映射。Head 包含戴帽者的头，不能映射为 no_helmet。论文扩展标注含 Helmet on/off，但本次取得的标准 YOLO 五列标签与抽查 VOC 文件没有这项属性；必须另获扩展属性或逐人复核。人物旁有 Helmet 也不能直接推定佩戴。
- **PDCS**：原始标签只有人员框。视频元数据中的 helmet yes/no 不是逐人的头部标签。头框和状态须另做。
- **HWD2024**：保留原始颜色、佩戴和人员类；先确认重叠框与定义，再导出。数据许可尚未核实，不直接进入客户业务训练集。

## 制作与质检实践

1. **先统一口径再批量标**：先取覆盖远景、多人、俯视、弯腰、普通帽、手持/地面帽、阴影的样本做试标；所有标注者用同一规范修订分歧。
2. **原图保真**：保存原始文件和 SHA-256；显示可以等比缩放，坐标以原图为准。EXIF 旋转必须与标签同步处理。不能把低清小图插值放大后记成高清。
3. **自动标注只作候选**：保存教师模型版本、置信度和来源。低置信度、多模型分歧、小头部、多人重叠优先复核；模型未检测到安全帽不等于未戴帽。逐图检查遗漏，而不是只检查已有框。
4. **不确定目标不能默认为背景**：普通 YOLO 检测训练没有自动启用的 ignore 区域。含未解决 uncertain 头部的图片暂缓导出状态检测训练，或裁出已解决且不包含未知目标的区域；不能删掉 uncertain 框后照常训练。
5. **重点复核关联和难例**：客户第 5 张“人旁地面有帽”和第 7 张“黑色头部覆盖物”分别检查；黑色不代表无帽，黄色也不代表戴帽。看不清时保留不确定。
6. **分组后划分**：同视频、同摄像头、同工地、同一拍摄系列的近似画面归为一组；尽可能按工地划分，再跨来源查重复。不能把相邻视频帧随机散入 train/val/test。帧数不等于独立场景数量。
7. **真值独立核验**：训练标签优先复核全部头部；验证/测试集逐图独立复核，疑难例裁决后冻结。若只有一位复核者，明确记录，不能声称完成双人复核。未审核候选不得写成用户已确认或自动发布。
8. **入库验收**：图像可解码、尺寸一致、无越界/非法类别、框非零面积、原图与标注可追溯；叠加框与原图放大检查；空标签须确认无目标，不能由下载或推理失败产生。

## 高质量素材优先级与时间证据

优先真实施工监控式远景、多种工地与摄像头、与客户相近的头部像素尺寸、可辨别佩戴状态和丰富姿态。近景高清宣传照可少量补充外观，但不能代替业务远景。复古风格、明显历史场景、广告水印遮挡目标、严重虚焦与强摆拍偏差降低优先级或排除。黑白/色调仅是风格证据，不单独推定拍摄年份。

采集年、上传年、发布年和 ZIP 文件修改时间分别记录。CMOT、SH17 的发布或上传时间不能证明每张图为 2020 年后实拍；当前未取得的采集年标 null，不填推测值。客户 41 张已参与选材，称为客户开发/案例评估集；不称作完全未见过的最终独立测试集。
