# 训练调度器租约、心跳与故障恢复设计

## 1. 背景与目标

当前本地训练管理器通过同机文件锁保证一个训练目录只有一个调度线程，并通过数据库事务避免同时领取多个任务。该方式适合单机 SQLite，但生产切换 MySQL、部署多个后端实例后，不同主机无法共享文件锁。现有启动恢复还会把所有活动任务直接标记为中断，无法区分仍被其他实例管理的任务。

本次改造目标：

- 保持本地 SQLite 单实例行为；
- 使用数据库租约保证多个后端实例中最多一个训练调度器领取任务；
- 使用任务所有权、执行代次和心跳阻止旧实例覆盖新状态；
- 在正常关闭、管理器崩溃、子进程消失、租约丢失时产生确定状态；
- 保留当前停止、续训、日志、配置快照和模型注册语义；
- 不向公共 API 暴露 PID、所有者标识、服务器路径或原始异常。

## 2. 范围

### 2.1 包含

- 同机文件锁与数据库调度器租约的组合；
- 调度器租约获取、续租、释放和过期接管；
- 训练任务所有权、执行代次和任务心跳；
- 活动任务的安全状态更新与故障恢复；
- 管理页面的安全诊断和操作建议；
- SQLite、MySQL、服务生命周期和并发回归测试。

### 2.2 不包含

- 自动重启或自动续训中断任务；
- 同一任务并行使用多张 GPU；
- 远程训练执行器；
- Kubernetes 作业调度器；
- 数据质量治理、模型效果分析、CI 与 Docker 改造。

## 3. 总体架构

采用“同机文件锁 + 数据库租约 + 任务心跳”的组合方案。

1. 每个 `LocalTrainingManager` 启动时生成不可预测的 `owner_id`。
2. 管理器先获取训练运行目录中的 `.training-manager.lock`，阻止同机重复管理器。
3. 管理器再原子获取 `training_scheduler` 单例行的租约。
4. 只有同时持有文件锁和有效数据库租约的管理器可以领取任务。
5. 管理器按固定间隔续租；每次检查子进程时同时更新任务心跳。
6. 所有活动任务更新都必须匹配 `owner_id` 与 `execution_generation`。
7. 租约过期后，新管理器才可接管调度权，并处理心跳已经超过恢复宽限期的遗留任务。

文件锁解决同一训练目录和同一 GPU 被同机进程重复使用的问题；数据库租约解决不同主机或容器共享 MySQL 时的调度互斥问题。两者不能相互替代。

## 4. 数据模型

新增迁移，扩展已有表，不创建第二套任务系统。

### 4.1 `training_scheduler`

在现有单例行上增加：

- `owner_id VARCHAR(64) NULL`：当前租约持有者；
- `heartbeat_at DATETIME NULL`：最后成功续租时间；
- `lease_expires_at DATETIME NULL`：租约失效时间；
- `revision INTEGER NOT NULL DEFAULT 0`：每次所有权变更递增。

`owner_id` 仅用于内部条件更新，不进入日志和公共 DTO。

### 4.2 `training_job`

增加：

- `owner_id VARCHAR(64) NULL`：当前执行所有者；
- `heartbeat_at DATETIME NULL`：当前执行心跳；
- `execution_generation INTEGER NOT NULL DEFAULT 0`：每次从 `queued` 被领取时递增。

终态任务清空 `owner_id`、`heartbeat_at` 和 PID，但保留 `execution_generation` 作为历史并发令牌。历史任务迁移后所有者与心跳为空、执行代次为 0，不改变原状态。

## 5. 租约协议

### 5.1 获取

在单个数据库事务中锁定 `training_scheduler` 单例行。满足以下任一条件时允许获取：

- 当前没有所有者；
- 当前所有者就是本管理器；
- `lease_expires_at` 早于数据库当前时间。

获取成功时写入新的 `owner_id`、心跳和过期时间，并递增 `revision`。失败时管理器释放同机文件锁并以“调度器不可用”状态运行，不能领取任务。

### 5.2 续租

续租必须以 `owner_id + revision` 为条件更新。更新失败表示所有权已丢失，管理器立即停止领取任务并进入隔离处理。

### 5.3 释放

正常关闭时，以 `owner_id + revision` 为条件清空租约字段。旧实例不得释放后来实例持有的租约。进程崩溃时不依赖释放，等待过期即可。

### 5.4 时间来源

租约判断使用数据库可比较的 UTC 时间。业务测试注入可控时钟。应用节点之间的时钟偏差通过恢复宽限期吸收，不允许仅凭本机 PID 判断跨主机所有权。

## 6. 任务领取与状态更新

领取任务必须同时满足：

- 调度器租约属于当前 `owner_id + revision` 且未过期；
- 没有仍处于活动状态且心跳有效的训练任务；
- 候选任务仍为 `queued`。

领取成功时原子写入：

- `status=running`；
- 当前 `owner_id`；
- `execution_generation + 1`；
- `started_at`、`heartbeat_at`、`updated_at`。

启动子进程后再写入 PID。若启动或 PID 持久化失败，管理器终止已经创建的子进程，并使用相同所有权令牌将任务置为失败。

进度、评估状态、停止状态和终态更新都必须匹配：

```text
job_id + owner_id + execution_generation + 允许的前置状态
```

匹配失败时不得重试覆盖；记录内部 `training_owner_mismatch`，重新读取当前状态并停止管理该任务。

## 7. 心跳与恢复

### 7.1 正常运行

管理器每次轮询子进程时更新任务心跳。只有持有有效租约时才能更新。进度文件没有变化时仍更新心跳，以区分“训练耗时”与“进程失联”。

### 7.2 正常关闭

服务关闭时：

1. 停止领取任务；
2. 当前任务进入停止流程；
3. 正常终止超时后强制结束子进程；
4. 根据 `last.pt` 是否有效记录 `stopped` 或 `interrupted`；
5. 释放数据库租约和文件锁。

### 7.3 管理器崩溃

任务暂时保持原活动状态。新管理器获得过期租约后，仅处理 `heartbeat_at` 已超过恢复宽限期的任务，将其置为 `interrupted`。系统不自动创建续训任务，管理员确认后使用现有“恢复”操作从受控 `last.pt` 创建新记录。

### 7.4 租约丢失

管理器停止领取和更新任务。若当前子进程仍存活，先正常终止，超时后强制结束；在确认进程退出前保持隔离，不允许新训练启动。旧管理器不得把已经被新实例处理的任务写成终态。

### 7.5 子进程消失或结果损坏

- PID/进程消失且没有合法结果：`training_process_missing`；
- 心跳超过宽限期：`training_heartbeat_timeout`；
- 调度器租约丢失：`scheduler_lease_lost`；
- 所有权条件更新失败：`training_owner_mismatch`；
- 结果或制品校验失败：沿用已有稳定训练/评估错误码。

公共错误消息只提供安全、可操作的中文提示；详细异常类型写入受限日志，不写绝对路径和环境变量。

## 8. 配置

新增：

```dotenv
TRAINING_HEARTBEAT_SECONDS=5
TRAINING_LEASE_SECONDS=20
TRAINING_RECOVERY_GRACE_SECONDS=30
```

启动校验：

- 三项均为有限正数；
- `TRAINING_LEASE_SECONDS >= 3 * TRAINING_HEARTBEAT_SECONDS`；
- `TRAINING_RECOVERY_GRACE_SECONDS >= TRAINING_LEASE_SECONDS`。

默认值兼顾本地开发和普通网络抖动。配置会记录到启动日志，但不返回给未授权用户。

## 9. API 与页面

公共响应不增加 `owner_id`、PID、租约版本或绝对时间路径。训练目录响应增加全局 `scheduler_state`，任务 DTO 增加安全派生状态：

- `scheduler_state`：`healthy | unavailable | disabled`；
- `runtime_state`：`healthy | heartbeat_delayed | disconnected`；
- `recovery_hint`：稳定枚举，由前端映射中文建议。

页面行为：

- 有任一实例持有有效租约时均视为调度器正常，用户可以从任意后端实例创建排队任务；
- 全局调度器不可用或训练已禁用时禁用“新建训练”，并显示明确原因；
- 心跳短暂延迟只提示，不立即宣告失败；
- 任务被标记中断后提示检查 `last.pt` 并使用“恢复”；
- 不提供“自动强制接管”按钮，避免误杀仍在工作的进程。

## 10. 测试策略

### 10.1 仓储与迁移

- SQLite/MySQL 新字段迁移和历史行默认值；
- 租约首次获取、续租、条件释放、过期接管；
- 两个所有者并发竞争只有一个成功；
- 旧 `owner_id/revision` 不能更新任务或释放新租约；
- 执行代次随每次领取递增。

### 10.2 管理器

- 单实例领取、运行、评估和完成；
- 第二实例在租约有效期内不能领取；
- 崩溃后必须等待租约与恢复宽限期；
- 续租失败触发隔离并终止本实例子进程；
- PID 持久化失败不会遗留训练进程；
- 停止超时、心跳超时、进程消失和所有权冲突均映射稳定结果；
- 锁接管测试等待“任务已经领取且子进程已经启动”的完整观察条件，消除断言竞态。

### 10.3 API、前端与生命周期

- 公共 DTO 不泄露内部租约字段；
- 调度状态、错误提示和禁用操作正确；
- 启动失败不会错误恢复其他实例的任务；
- 正常关闭释放资源；
- 当前停止、续训、复制、删除、注册模型流程保持兼容。

## 11. 验收标准

- SQLite 单实例行为和现有测试保持通过；
- 共享 MySQL 的两个应用实例中最多一个管理器能够领取训练任务；
- 旧实例不能覆盖新实例已经更新的任务；
- 管理器崩溃后，任务只在租约和宽限期到期后转为 `interrupted`；
- 正常关闭、租约丢失和子进程消失均不会遗留可继续运行的孤儿训练进程；
- 所有公共响应不包含所有者令牌、PID、绝对路径或原始异常；
- 并发锁接管测试连续执行不再出现时序失败。
