# 训练集版本与人工标注设计

**日期：** 2026-08-22  
**状态：** 已确认  
**范围：** 服务器训练集版本管理、现有图片的 YOLO 检测框人工标注、校验与发布

## 1. 背景与目标

当前系统可以从服务器授权目录定义训练集并创建训练任务，但训练集记录直接指向可变目录，控制台也不能查看或修正图片标签。Construction-PPE 派生数据只完成了 `Person`、`helmet`、`no_helmet` 的类别映射，没有补齐所有“人员头部未匹配安全帽”的 `no_helmet` 漏标。继续增加训练轮次不能解决错误监督问题。

本功能在“模型管理 → 训练集”中增加版本管理和内置人工标注工作台。管理员从已发布训练集复制一个编辑版本，在副本中修改现有图片的检测框和类别，完成校验后发布为新的只读版本。训练任务始终绑定具体已发布版本，历史训练结果可复现，正在训练的数据不会被编辑影响。

## 2. 第一版范围

第一版支持：

- `train`、`val`、`test` 三个分区使用相同的标注能力，首次进入默认选择 `test`；
- 从任意已发布版本完整复制出新的编辑版本；
- 浏览现有图片和 YOLO 标注；
- 使用鼠标新增、移动、缩放和删除矩形检测框；
- 修改框的类别；
- 增加或重命名数据集类别，安全删除未使用类别；
- 自动保存单图标注、并发冲突检测和失败恢复；
- 数据集级结构校验、语义警告和发布；
- 已发布版本只读，并可供训练任务选择。

第一版不支持：

- 上传、删除或替换图片；
- 在 `train`、`val`、`test` 之间移动图片；
- 多边形、分割掩码、关键点或旋转框；
- 自动生成未经人工确认的正式标签；
- 外部 CVAT、Label Studio 或远程标注服务集成；
- 为新增类别自动创建告警业务规则。

## 3. 版本模型与状态

每条训练集记录表示一个具体版本。现有训练集迁移为 `v1 / published`。版本新增以下语义字段：

- `version`：同一版本链内递增的正整数；
- `status`：`editing` 或 `published`；
- `parent_id`：复制来源版本，可为空；
- `published_at`：成功发布的 UTC 时间；
- `revision`：数据集级乐观锁版本；
- `manifest_digest`：发布时生成的数据摘要，可为空。

状态规则：

- `editing` 允许修改类别和标签，但不能被训练任务选择；
- `published` 永久只读，可以被训练任务选择；
- 已发布版本需要修改时必须复制为新的 `editing` 版本；
- 训练任务继续通过 `training_dataset_id` 绑定具体版本；
- 停用只影响新训练任务是否可选择，不改变版本内容和历史引用。

数据库增加图片编辑索引表。每个图片条目至少保存数据集版本、分区、内部相对键、展示文件名、宽高、检查状态、单图 revision 和更新时间。图片与 YOLO 标签文件仍是训练的权威数据；数据库负责分页、筛选、并发控制和检查进度，不保存第二份框坐标副本。

## 4. 复制与文件安全

点击“创建编辑版本”时，后端执行以下步骤：

1. 验证源版本为已发布状态，并位于配置的服务器授权根目录内；
2. 检查目标目录冲突和可用空间；
3. 将整个数据集复制到同一授权根下的受控临时目录，忽略 `*.cache` 等可重建缓存；
4. 扫描图片，验证对应分区和标签目录，创建图片索引；
5. 原子重命名临时目录，并在同一成功路径中创建 `editing` 版本记录；
6. 任一步骤失败时删除临时副本，不暴露半成品版本。

所有文件访问必须通过 `resolve()` 后的根目录 containment 检查，拒绝绝对路径、`..`、Windows drive、UNC、POSIX 绝对路径和符号链接逃逸。API 只暴露数据库 ID、展示名称和受保护资源 URL，不返回服务器绝对路径。

## 5. 类别管理

标注类别由当前编辑版本的类别数组动态提供，不在前端写死。

- 新增类别只能追加到数组末尾，获得新的 YOLO 类别 ID；
- 重命名类别只改变名称，不改变 ID；
- 不允许重排类别；
- 类别名称必须非空、长度受限、在当前版本内唯一；
- 删除类别前统计全部分区的使用量，只有使用量为零时允许删除；
- 已发布版本的类别不可修改；
- `person`、`helmet`、`no_helmet` 之外的新类别可以参与训练和推理，但不会自动拥有告警规则。

## 6. 标注工作台

从编辑版本卡片点击“继续标注”进入独立页面。

### 6.1 页面布局

- 顶部：训练集名称、版本、状态、`train / val / test` 切换、保存状态、校验和发布入口；
- 左侧：分页图片缩略图，可筛选全部、未检查、已修改和有错误；
- 中间：保持图片比例的 Canvas 标注画布；
- 右侧：类别选择、当前图片标注列表、类别统计和校验消息；
- 底部：上一张、下一张、保存并下一张。

颜色默认使用 `person` 蓝色、`helmet` 绿色、`no_helmet` 红色；其他类别从稳定调色板按类别 ID 取色。

### 6.2 鼠标和键盘操作

- 选择或锁定类别后，按住鼠标左键从一个角拖到对角，松开后创建框；
- 拖动框内部移动框，拖动四角或四边控制点调整大小；
- 点击重叠框时优先选择最上层框，并允许从标注列表精确选择；
- 鼠标滚轮缩放，拖动画布平移；所有坐标按原图尺寸换算；
- 框始终限制在图片边界内，过小的误触框不保存；
- `Esc` 或鼠标右键取消正在绘制的框；
- `Delete` 删除选中框，`Ctrl+S` 保存，方向键切换图片；
- 支持撤销和重做；
- 锁定类别后可连续绘制同一类别的多个框。

YOLO 坐标在后端统一验证并规范化为 `class_id x_center y_center width height`。前端显示像素坐标，传输使用归一化坐标，避免显示尺寸和缩放改变真实标签。

## 7. 保存、并发与恢复

每次编辑后短暂延迟自动保存。页面必须明确显示“未保存、保存中、已保存、保存失败”。切换图片前先完成保存；保存失败时保留当前图片和本地编辑状态。

保存请求携带单图 `revision`。后端在数据库事务内比较 revision，冲突返回稳定的 `409 annotation_conflict`，不得覆盖另一页面的新版本。标签内容先写入同目录随机临时文件，完成 flush 后通过 `os.replace` 原子替换；数据库 revision 仅在文件替换成功后更新。若数据库提交失败，服务需要恢复原标签或保持可检测、可重试的一致状态。

浏览器为当前图片保留尚未提交的短期恢复副本。刷新后若服务器 revision 未改变，可以提示恢复；若服务器已有新 revision，则必须提示冲突，不能静默覆盖。

## 8. 校验与发布

发布前扫描三个分区的所有图片和标签。

### 8.1 阻止发布的错误

- 图片无法安全解码；
- 标签行不是五列；
- 类别 ID 不存在；
- 坐标不是有限数值或超出 `[0, 1]`；
- 标注框宽或高不大于零；
- 图片与标签目录结构不符合配置；
- 文件逃逸授权根目录；
- 版本状态不是 `editing`，或同一版本已有发布操作。

空标签文件允许作为有效负样本，不作为结构错误。

### 8.2 允许确认后发布的警告

- 图片没有任何标注；
- `person` 的头部区域没有匹配到 `helmet` 或 `no_helmet`；
- `helmet` 与 `no_helmet` 在同一头部区域明显重叠；
- 某类别样本数量过少；
- train、val、test 的类别分布差异明显。

校验报告按错误类型汇总，并提供可跳转的图片 ID。结构错误必须全部修复；只有警告时管理员需要二次确认。

发布成功时，后端生成包含版本、类别、分区、图片和标签摘要的清单及 SHA-256 摘要，然后在事务中将状态原子切换为 `published`。发布后所有标注、类别和文件写接口返回 `409 dataset_published`。

## 9. API 边界

受保护的管理接口覆盖：

- 从已发布训练集创建编辑版本；
- 获取版本链和统计；
- 分页筛选图片；
- 获取单图元数据、标注和受保护图片内容；
- 使用 revision 保存单图标注；
- 新增、重命名和安全删除类别；
- 校验编辑版本并获取报告；
- 确认警告并发布版本。

所有写操作要求管理员权限和同源校验。图片响应使用精确 MIME、`nosniff` 和内联展示策略。错误响应使用稳定中文可映射的错误码，不包含提交内容、YOLO 原始异常、SQL、绝对路径或 traceback。创建版本、保存标注、修改类别、校验和发布均记录脱敏审计事件。

## 10. 训练集页面集成

“模型管理 → 训练集”按数据集版本链展示卡片：

- 已发布版本显示“创建编辑版本”“查看标注”和状态徽标；
- 编辑版本显示“继续标注”“校验发布”和编辑进度；
- 版本历史展示父版本、版本号、创建人、发布时间和图片/标注统计；
- 训练任务下拉框只显示已发布且启用、当前文件校验有效的版本；
- 历史任务仍显示其绑定版本，即使该版本后来被停用。

## 11. 测试策略

后端重点测试：

- 迁移现有训练集为 `v1 / published`；
- 原子复制、空间/IO 失败清理和缓存排除；
- 路径 traversal、drive、UNC、POSIX 和 symlink containment；
- YOLO 解析、有限数值、范围、类别和空标签；
- 原子写失败不破坏原文件；
- revision 并发冲突；
- 类别 ID 稳定、使用中类别拒绝删除；
- 结构错误阻止发布、警告二次确认、发布后不可变；
- 编辑版本不能训练、发布版本可以训练；
- 管理员权限、同源要求、资源响应头和日志脱敏。

前端重点测试：

- 分区切换、图片筛选和版本状态；
- 鼠标拉框、移动、八向缩放和边界限制；
- 缩放/平移后的坐标换算；
- 类别锁定、动态类别、撤销/重做和快捷键；
- 自动保存状态、失败保留和 revision 冲突提示；
- 校验报告、错误跳转、警告确认和发布后只读。

验收使用本地 SQLite 和复制出的临时数据集执行，不修改 `datasets/construction-ppe`、`datasets/construction-ppe-helmet` 或正在运行任务的目录。MySQL 实机与生产部署继续作为独立验收边界。

## 12. 部署顺序

当前训练任务运行期间只编写和验证代码，不修改数据集、不执行数据库迁移、不重启服务。训练任务结束后依次执行：

1. 备份数据库和数据集目录；
2. 构建前端；
3. 停止服务；
4. 执行显式数据库迁移；
5. 启动服务并确认现有训练集已迁移为只读 v1；
6. 从 v1 创建编辑副本，完成少量标注、校验和发布烟测；
7. 确认新发布版本可创建训练任务，原版本与历史任务未变化。
