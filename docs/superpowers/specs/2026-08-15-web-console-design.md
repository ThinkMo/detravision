# Safety Detect 管理前端、登录与多图识别设计

## 1. 背景与目标

当前仓库是基于 FastAPI、SQLite 和 Ultralytics 的后端 MVP，已经提供摄像头、人员、告警组、事件、模型版本、实时 JPEG WebSocket 和 RTSP 推理运行时，但没有管理前端、用户身份体系或图片上传识别接口。

本次工作交付一个现代化的管理网站，并补齐与网站配套的后端能力：

- 网站名称和 Logo 可由管理员配置；
- 本地账号密码登录，区分管理员和普通用户；
- 实时画面、事件、设备、告警组和模型的可视化管理；
- 单次最多上传 20 张图片进行识别，保存任务历史、标注结果并支持下载；
- 默认继续使用 SQLite，同时允许通过连接配置切换到 MySQL；
- 前端和后端同源、同端口部署。

## 2. 范围

### 2.1 本期包含

- React + TypeScript 单页管理前端；
- FastAPI 静态资源托管和单页应用回退；
- 本地用户、服务端会话、角色权限、强制首次改密和登录限速；
- 默认管理员引导创建；
- 品牌设置和 Logo 上传；
- 多图上传、异步识别、任务历史、结果展示和 ZIP 下载；
- 现有 REST API 和 WebSocket 的身份校验；
- SQLAlchemy 2 数据访问层和 Alembic 数据库迁移；
- SQLite 与 MySQL 配置切换；
- 30 天批量识别文件和任务清理；
- 审计日志、自动化测试和真实模型冒烟验收。

### 2.2 本期不包含

- 公开注册、短信或邮件找回密码；
- 企业微信、飞书、LDAP 或 OIDC 单点登录；
- 多租户和细粒度自定义权限；
- 对象存储实现、多实例任务调度和分布式限流；
- WebRTC/HLS 高并发视频分发；
- 在网页内训练或上传模型文件。

这些能力可在现有接口边界之上扩展，不影响本期数据模型和页面结构。

## 3. 总体架构

采用前后端同源的一体化部署：

```text
Browser
  ├─ React SPA (/)
  ├─ REST API (/api/*)
  └─ WebSocket (/ws/*)
          │
       FastAPI
  ┌───────┼───────────┐
  │       │           │
认证/权限 业务服务   推理协调器
  │       │       ┌───┴────────┐
  └──── SQLAlchemy │实时 RTSP 队列│
          │        │多图任务队列 │
     SQLite/MySQL  └────┬───────┘
                        │
                 Ultralytics Detector
```

前端源码放在独立的 `frontend/` 目录。生产构建产物由 FastAPI 提供，`/api` 与 `/ws` 路由优先于 SPA 回退；未知页面路径返回前端入口以支持客户端路由。开发时可使用前端开发服务器代理 FastAPI，但生产只暴露一个地址。

后端按认证、品牌、批量识别、存储和推理协调进行模块化拆分。每个模块通过明确的服务接口访问数据库或文件系统，不允许路由直接拼接 SQL。

## 4. 数据库与迁移

### 4.1 数据库抽象

引入 SQLAlchemy 2 ORM 和 Alembic。环境变量 `DATABASE_URL` 决定数据库：

- 默认：`sqlite:///data/safety_detect.db`；
- MySQL 最低支持 8.0.13，示例：`mysql+pymysql://user:password@host:3306/safety_detect?charset=utf8mb4`。

模型只使用 SQLite 和 MySQL 都支持的字段、索引和外键。ROI、检测类别、状态、运行时、边界框和识别结果统一以 `TEXT` 存储；需要默认值的 `TEXT` 使用 MySQL 8.0.13 起支持的括号表达式写法。JSON 数据在仓储边界序列化，避免依赖数据库特有 JSON 查询语法。时间统一按 UTC 写入，API 输出 ISO 8601 时间。

### 4.2 兼容现有数据库

迁移历史包含一个与当前六张业务表一致的 legacy baseline，以及后续认证、品牌、批量任务和审计表迁移。迁移命令按以下规则执行：

1. 新数据库从 baseline 正常创建全部旧表，再升级到最新版本；
2. 已存在旧表但没有 `alembic_version` 的数据库先校验旧表关键列，标记为 legacy baseline，再执行增量迁移；
3. 结构与 legacy baseline 不一致时停止并输出明确错误，不猜测或覆盖现有数据；
4. 生产部署显式运行迁移，应用启动过程不擅自修改生产数据库结构。

现有原始 SQLite 仓储会完整迁移到 ORM 仓储，REST 路径和响应字段保持兼容。

## 5. 身份与权限

### 5.1 用户与默认管理员

系统不开放注册。首次启动迁移完成后，如果用户表为空，则创建用户名 `admin` 的管理员：

- 初始密码优先读取 `ADMIN_INITIAL_PASSWORD`；
- 本地开发模式未配置密码时使用 `admin123456`；
- 生产模式未配置初始密码时拒绝启动；
- 初始管理员首次登录后必须修改密码，改密前只能访问当前用户、退出和修改密码接口。

密码使用适合密码存储的强哈希算法及随机盐保存，不存储、记录或返回明文密码。

### 5.2 会话

登录成功后创建服务端会话。浏览器 Cookie 只保存不可预测的原始令牌，数据库仅保存令牌哈希。Cookie 设置 `HttpOnly`、`SameSite=Lax`，生产 HTTPS 下设置 `Secure`。会话具有绝对过期时间和最后活动时间，退出、用户禁用或管理员重置密码时相关会话立即失效。

修改类请求校验同源 `Origin`/`Referer`，防止跨站请求。登录按 IP 与用户名组合限速；当前单实例采用进程内限速器，未来多实例部署时替换为共享限流存储。

### 5.3 角色

| 能力 | 管理员 | 普通用户 |
|---|---:|---:|
| 查看工作台、实时画面、事件 | 是 | 是 |
| 上传多图、查看自己的任务 | 是 | 是 |
| 查看所有用户的批量任务 | 是 | 否 |
| 确认或关闭事件 | 是 | 是 |
| 管理摄像头、人员和告警组 | 是 | 否 |
| 登记、激活模型 | 是 | 否 |
| 修改网站品牌、管理用户、查看审计日志 | 是 | 否 |

权限由后端逐接口强制执行。前端隐藏无权入口只用于改善体验，不能作为安全边界。WebSocket 在握手阶段校验会话；未登录或无权限时关闭连接。

## 6. 品牌配置

`site_settings` 保存单例品牌配置，至少包含网站名称和 Logo 路径。默认网站名称为 `Safety Detect`，未上传 Logo 时使用前端内置的文字图标占位。

管理员可在系统设置中修改名称和上传 Logo。Logo 仅接受经过内容检测的 PNG、JPEG 或 WebP，限制文件大小和图像尺寸，并使用服务端生成的文件名保存，禁止使用客户端路径。更新成功后，登录页、侧栏、页面标题和浏览器标题立即刷新。替换 Logo 后，旧文件在新配置事务成功后删除；删除失败记录日志并由清理任务重试。

## 7. 页面与交互

### 7.1 视觉方向

整体采用现代管理控制台风格：深色侧边栏、浅色内容区、青绿色表示正常和安全状态、橙红色表示告警。信息密度适合桌面监控场景，同时适配平板和手机。所有表单、对话框、状态色和键盘操作满足基础可访问性要求。

### 7.2 页面

- **登录页**：品牌 Logo、网站名称、账号密码表单和可理解的错误提示；
- **首次改密页**：初始管理员或被重置密码的用户必须设置新密码；
- **工作台**：摄像头在线数、今日告警、待确认事件、近期事件和系统运行状态；
- **实时监控**：摄像头卡片列表和单路大画面，展示连接及推理状态；
- **多图识别**：拖拽/选择图片、上传进度、任务进度、按图结果、失败原因及下载操作；
- **事件中心**：按摄像头、类型、状态和时间筛选，查看抓拍并确认或关闭；
- **设备与告警**：管理摄像头、人员和告警组；
- **模型管理**：查看、登记和激活模型；
- **系统设置**：管理员修改品牌、管理用户、重置密码并查看审计日志。

根地址根据会话状态跳转到登录页或工作台。无权页面显示 403 状态页；未知页面显示 404 状态页；会话失效时保留当前目标地址并跳转登录。

## 8. 多图识别

### 8.1 上传约束

- 单次最多 20 张；
- 每张最多 10 MB；
- 接受 PNG、JPEG 和 WebP；
- 同时校验扩展名、MIME 和实际解码结果；
- 原始文件名仅用于页面显示，磁盘文件名由服务端生成；
- 图片尺寸设置安全上限，防止解压炸弹和异常内存占用。

请求创建任务后立即返回任务 ID，识别在后台逐张执行。前端轮询任务状态，不用长请求等待整批完成。

### 8.2 推理协调

实时 RTSP 与多图任务共享当前激活模型。新增线程安全的检测器提供者负责原子切换模型和保护单模型推理调用。批量任务由有界单工作线程处理，每完成一张图片便释放推理锁，使实时队列可以继续消费，避免一次批量任务长时间独占 GPU。

模型未加载时拒绝新任务并返回可理解的业务错误。任务执行期间模型被激活切换时，已经开始的单张图片使用旧实例完成，后续图片使用新实例；每张结果记录实际模型版本，保证结果可追溯。

### 8.3 任务和结果

任务状态为：

- `queued`：等待处理；
- `processing`：至少一张正在处理；
- `completed`：全部成功；
- `partial_failed`：部分成功、部分失败；
- `failed`：全部失败或任务级错误。

每张图片保存原图路径、标注图路径、状态、错误信息、模型版本和结构化检测结果。检测结果包含类别、置信度和像素坐标边界框，页面对类别保持通用展示，不硬编码为安全帽类别。

单张失败不阻断其他图片。用户可查看和下载自己的任务；管理员可查看全部任务。单图结果直接下载，整批结果按请求生成 ZIP，包含标注图和 JSON 汇总，不长期保存重复压缩包。

原图、标注图和任务记录默认保留 30 天。定时清理任务先删除文件、再删除数据库记录；单项失败记录原因并在下一轮重试。

## 9. 数据模型

新增主要表如下：

- `user`：用户名、密码哈希、角色、启用状态、强制改密标记和时间戳；
- `user_session`：令牌哈希、用户、过期时间、最后活动时间和创建信息；
- `site_settings`：网站名称、Logo 路径和更新时间；
- `batch_job`：创建人、状态、图片总数、成功数、失败数、过期时间和时间戳；
- `batch_image`：所属任务、显示文件名、原图/结果路径、状态、错误、模型版本和检测结果；
- `audit_log`：操作人、动作、资源类型、资源 ID、结果、来源 IP 和时间。

现有 `detection_event.ack_by` 继续关联告警联系人以兼容旧数据；新增可空的
`ack_user_id` 关联登录用户，用于记录网页端实际确认或关闭事件的操作人。事件
状态接口返回两个字段，审计日志同时记录登录用户，不混用两类 ID。

用户名、会话令牌哈希和必要的查询组合建立唯一索引或普通索引。所有外键明确删除策略；任务删除级联删除图片记录，但文件删除由存储服务显式执行。

## 10. API 设计

新增接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | 登录并创建会话 |
| POST | `/api/auth/logout` | 注销当前会话 |
| GET | `/api/auth/me` | 当前用户和权限信息 |
| POST | `/api/auth/change-password` | 修改当前用户密码 |
| GET / POST | `/api/users` | 管理员查询、创建用户 |
| PATCH | `/api/users/{id}` | 修改角色或启用状态 |
| POST | `/api/users/{id}/reset-password` | 管理员重置密码并使会话失效 |
| GET / PATCH | `/api/settings/site` | 读取或修改网站名称 |
| POST | `/api/settings/site/logo` | 上传并替换 Logo |
| POST | `/api/batch-jobs` | 上传多图并创建任务 |
| GET | `/api/batch-jobs` | 查询可见任务 |
| GET | `/api/batch-jobs/{id}` | 查询任务和逐图结果 |
| GET | `/api/batch-jobs/{id}/images/{image_id}/download` | 下载单张标注图 |
| GET | `/api/batch-jobs/{id}/download` | 下载整批 ZIP |
| GET | `/api/audit-logs` | 管理员查询审计日志 |

现有接口路径保持不变，但除健康检查和登录所需的公开品牌信息外均要求登录。管理摄像头、人员、告警组和模型的写操作要求管理员；事件确认和关闭允许普通用户。健康检查不返回敏感配置。

所有错误使用统一结构，包含稳定错误码、面向用户的消息和可选字段错误；内部堆栈、数据库异常和本地路径不返回浏览器。

## 11. 文件存储

定义文件存储接口，负责保存、打开、删除原图、标注图和 Logo。首版实现使用项目配置目录下的本地文件系统，并按用途、日期和任务 ID 分层。数据库只保存存储键，不保存任意绝对路径。

写文件采用临时文件加原子替换；数据库事务失败时清理由本次请求产生的文件。下载响应统一设置安全的内容类型和文件名。接口边界允许后续增加 S3、MinIO 或其他对象存储实现而不修改业务路由。

## 12. 异常处理与可观测性

- 图片损坏或格式错误：在上传阶段拒绝，并指出对应文件；
- 部分图片推理失败：任务进入 `partial_failed`，保留成功结果；
- 模型未加载：拒绝创建任务，实时监控显示模型不可用；
- 存储空间不足：当前图片标记失败，记录结构化错误，不返回磁盘路径；
- 数据库不可用：请求返回服务不可用，后台任务停止领取新工作；
- WebSocket 断线：前端指数退避重连并显示断线状态；
- 应用重启：启动时将遗留 `processing` 任务恢复为 `queued`，继续未完成图片；
- 清理失败：记录任务、存储键和原因，下次周期重试。

关键操作写入审计日志：登录成功/失败、退出、改密、用户管理、品牌修改、摄像头与模型修改、事件状态变更和批量任务创建。应用日志不得包含密码、Cookie、会话原始令牌、RTSP 凭据或上传图片内容。

### 13.1 自动化测试

- 密码哈希、会话创建/失效/过期和强制改密；
- 管理员、普通用户、未登录三类身份的接口权限矩阵；

- 品牌名称和 Logo 上传、替换、校验与失败清理；
- 文件数量、大小、类型、图像尺寸和路径安全校验；
- 多图任务状态转换、部分失败、重启恢复、模型版本记录和过期清理；
- SQLite 完整测试套件；
- MySQL 环境下执行迁移和核心仓储增删改查测试；
- 前端登录、强制改密、权限导航、批量上传进度、部分失败和品牌刷新；
- 现有规则引擎、帧队列和训练 CLI 回归测试。

### 13.2 最终验收路径

本轮以本地 SQLite 单机运行作为交付验收目标。MySQL 连接能力、迁移代码和可执行测试继续保留，但 MySQL 实机验收与生产部署延后到后续阶段。

1. 空数据库启动，使用默认 `admin` 和配置的初始密码登录；
2. 首次登录被要求修改密码，完成后进入工作台；
3. 修改网站名称和 Logo，登录页、侧栏和浏览器标题同步更新；
4. 创建普通用户，验证其可查看实时画面、事件并上传多图，但不能进入管理设置；
5. 使用真实训练模型上传包含多张图片的任务，查看进度、检测框、置信度和失败项；
6. 下载单张标注图及整批 ZIP，内容与页面结果一致；
7. 配置一条摄像头，验证实时画面和事件 WebSocket 在登录状态下工作；
8. 验证会话过期、用户禁用、密码重置和退出会立即阻止后续访问；
9. 运行前端生产构建、后端全量测试和 SQLite 到最新版本的迁移；
10. 保留 MySQL 迁移和核心仓储标记测试，待后续提供独立 MySQL 测试库时执行。

## 14. 完成标准

满足以下条件视为本期完成：

- 所有确认页面均可从根地址访问，桌面和平板主要流程可用；
- Logo、网站名称、用户和角色可由管理员配置；
- 所有现有业务 API 和 WebSocket 均受正确的身份和权限保护；
- 多图任务满足上传限制、异步处理、历史保存、逐图结果和下载要求；
- SQLite 是本轮本地验收数据库；MySQL 可通过 `DATABASE_URL` 和迁移命令启用，其实机验收延后；
- 旧 SQLite 数据库可无损进入 Alembic 迁移体系；
- 自动化测试与真实模型冒烟验收通过；
- README 包含开发启动、生产构建、初始管理员、数据库迁移、MySQL 切换和文件保留说明。
