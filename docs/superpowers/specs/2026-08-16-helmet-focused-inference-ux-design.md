# 安全帽违规识别体验优化设计

## 目标

实时监控与多图识别以“发现未佩戴安全帽的人”为首要目标。修复多图选择器重复打开、用户误认为不支持多选的问题，并让识别完成后的标注图直接显示在任务详情页，而不是触发浏览器下载。

## 范围

本次变更包含：

- 修复文件选择事件重复触发。
- 支持一次选择多张图片，以及分多次追加图片，单任务仍限制为最多 20 张、每张最多 10 MiB。
- 为标注结果提供独立的安全内嵌预览接口。
- 在多图结果与实时画面中优先突出 `no_helmet`。
- 保留单图标注结果与任务 ZIP 下载功能，但将下载降为次要操作。

本次不修改模型结构、类别定义、实时事件确认次数、事件冷却时间、用户权限模型、任务保留期或生产数据库策略。

## 根因与约束

### 重复文件选择窗口

隐藏的 `input[type=file]` 位于可点击上传区域内部。用户完成文件选择后，输入控件的点击事件继续冒泡到外层区域，外层再次调用 `input.click()`，导致文件选择窗口重新打开。

修复必须让文件输入或专用选择按钮独立处理点击，不允许一次用户操作触发第二次程序化点击。

### 多选体验

文件输入必须保留 `multiple`。用户可以：

- 在一次系统文件选择窗口中选择多张图片；
- 关闭窗口后再次选择并追加图片；
- 在上传前移除单张图片；
- 看见当前数量、总大小、重复文件和格式错误提示。

去重键继续使用文件名、文件大小和最后修改时间的组合。任何追加操作都不能清空已选中的合法图片。

### 结果图被当作下载

当前结果 URL 指向下载接口，响应包含 `Content-Disposition: attachment`。页面又把同一 URL 用作 `<img src>`，不同浏览器可能拒绝内嵌渲染或直接触发下载。

必须区分两种响应语义：

- 预览接口：`Content-Disposition: inline`，供受保护页面内的 `<img>` 使用；
- 下载接口：`Content-Disposition: attachment`，供用户显式下载。

两种接口都必须验证登录状态、任务所有权或管理员权限、图片归属和存储键路径边界。不得暴露磁盘路径或内部存储键。

## 后端设计

### 安全预览接口

新增：

```text
GET /api/batch-jobs/{job_id}/images/{image_id}/preview
```

行为：

- 仅允许已登录用户访问；普通用户只能访问自己的任务，管理员可以访问全部任务。
- 仅对状态为 `completed` 且存在标注结果的图片返回内容。
- 返回真实图片 MIME，设置 `Content-Disposition: inline`、`X-Content-Type-Options: nosniff`，并采用与下载接口一致的流式关闭逻辑。
- 任务不存在、图片不属于任务或用户无权访问时统一返回 404。
- 文件缺失或存储不可用时返回稳定错误，不在响应或日志中包含本地路径。

现有 `/download` 接口保持附件下载语义，不改变 ZIP 内容。

### DTO

每张已完成图片返回两个同源 URL：

- `preview_url`：仅允许匹配该任务和图片的预览路径；
- `result_url`：现有下载路径。

前端必须分别执行严格路径白名单校验，不能接受后端返回的任意 URL。

### 违规优先统计

推理结果仍持久化全部检测类别，不删除 `person` 或 `helmet`。API 在现有 detections 中计算或允许前端确定性计算：

```text
violation_count = label == "no_helmet" 的检测数量
```

这样保留完整模型证据，同时让页面以违规数量作为首要指标。

## 前端设计

### 上传区

- 上传区域使用一个明确的“选择图片”触发点；文件输入自身点击不得冒泡并再次触发外层点击。
- 拖放、键盘 Enter/Space 和点击按钮都复用同一个选择流程。
- 输入保留 `multiple` 和 PNG/JPEG/WebP accept 列表。
- 每次选择后清空 input value，以便后续再次追加同一文件；重复文件由业务去重提示处理。
- “开始识别”是独立按钮，点击不能打开文件选择窗口。
- 上传成功后进入任务详情；上传失败时保留当前选择，显示服务端稳定错误并允许重试。

### 任务结果页

处理中继续每秒轮询；进入最终状态后停止轮询。

每张成功结果卡的内容顺序为：

1. 内嵌标注图；
2. 醒目的“未佩戴安全帽：N 人”；
3. `no_helmet` 检测的置信度列表；
4. 弱化展示 `person`、`helmet` 等其他检测摘要；
5. 次要的“下载标注图”操作。

预览加载失败时显示可重试的占位状态，不自动触发下载。失败图片继续显示稳定错误信息。

### 实时监控

实时帧仍由服务端生成。标注配色调整为：

- `no_helmet`：高对比红色、较粗边框；
- `person`：低饱和蓝灰色；
- `helmet`：低饱和绿色；
- 其他类别沿用普通配色。

实时事件规则不变：安全帽违规仍按人员头部区域关联和既有连续帧、冷却规则产生事件。

## 错误处理

- 文件选择错误在上传区内显示，不丢失之前已接受的图片。
- 上传 HTTP 错误使用后端稳定错误码映射为中文提示。
- 预览 401 在图片区域显示加载失败；页面中的任务详情 API 仍负责触发现有会话失效流程。403/404 统一显示结果不可用，不暴露资源是否属于他人。
- 预览 5xx 显示“结果图暂时无法加载”，保留下载按钮供用户主动重试。
- 所有对象 URL、请求和轮询在页面卸载时释放或停止。

## 测试

### 前端

- 一次点击只调用一次文件输入，不重复打开窗口。
- 文件输入具有 `multiple`，一次选择多张图片均进入预览列表。
- 第二次选择追加图片，不覆盖第一次选择。
- 点击“开始识别”只提交，不打开文件窗口。
- 上传失败保留选择并允许重试。
- 成功任务使用 `preview_url` 内嵌结果图，以违规数量为首要摘要。
- 非白名单预览 URL 不渲染。
- 下载按钮仍指向附件下载 URL。

### 后端

- 预览接口返回 inline 图片和安全响应头。
- 普通用户无法预览其他用户任务，管理员可以预览。
- job/image 组合不匹配返回 404。
- 文件缺失、路径逃逸和存储异常不泄露本地路径。
- 下载接口仍返回 attachment，ZIP 行为不变。

### 回归

- 多图 API、批量 Worker、真实模型烟测保持通过。
- 实时标注颜色测试验证 `no_helmet` 优先，事件规则测试保持不变。
- 前端全量测试、类型检查和生产构建通过。

## 验收标准

- 用户单击上传区只看到一次文件选择窗口。
- Windows 文件选择器可一次多选，页面也支持多次追加，总数最多 20 张。
- 上传成功后自动打开任务详情，识别完成的标注图直接显示。
- 页面首先显示每张图片的未佩戴安全帽人数，其他类别弱化但仍可查看。
- 下载仅在用户点击下载操作时发生。
- 实时监控和多图识别都突出 `no_helmet`，且不改变既有告警业务规则。
